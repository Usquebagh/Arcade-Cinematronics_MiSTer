# Rip Off

Rip Off shares the JMI CCPU configuration and mirrored 8 KiB program map with
Star Castle. The CPU, timing, watchdog, ROM RAM, vector queue and renderer are
shared in `cinemat_machine`. Compatibility wrappers keep the existing Star
Castle component regressions intact.

## Game Selection and Controls

Each MRA sends one profile byte at HPS index 1 before the program at index 0:
`00` selects Star Castle, `01` selects Rip Off. The profile is consumed once
per ROM load; a legacy MRA without the byte defaults to Star Castle. Empty,
oversized, out-of-order and unknown profiles leave the machine stopped.
A profile transfer blanks and resets the old game until a new ROM load.

Rip Off uses separate controller inputs for both simultaneous players.
Player 1: Left/Right, Up or Thrust, and Fire; keyboard arrows and Space.
Player 2: the same controls on controller 2; keyboard A/D, W and F.
Start 1/2 and Coin retain the existing mappings (keyboard 1/2 and 5).
Service mode is logically On/Off in the OSD, with active-low electrical
polarity for Rip Off and active-high for Star Castle.

Rip Off defaults to monochrome. Star Castle's gel profile is bypassed while
vector brightness remains available; the colour-overlay option has no effect
on Rip Off. No cabinet artwork or speculative colour filter is applied.

## Sound Board

`ripoff_sound` follows the manual's audio-board schematic (PDF page 80,
printed 8-18). Serial data is OUT0, the LS164 clock is rising OUT1, and the
LS377 commit is rising OUT2. Only six latch inputs are connected; D6/D7 are
grounded. The six effects are:

| Effect | Control |
| --- | --- |
| Explosion | OUT7 low; 555 monostable plus filtered noise/envelope |
| Laser | OUT4 low; swept VCO and weighted LS393 divider outputs |
| Torpedo | OUT3 low; a separate swept VCO/divider |
| Background | Latched bit 3 low; bits 0-2 select the resistor-DAC pitch |
| Beep | Latched bit 4 low; IC5 555 oscillator |
| Motor | Latched bit 5 low; IC11/IC13 oscillators |

The model updates at 96 kHz. Short explosion triggers are retained between
sample enables. Reset/download mute and clear the board; watchdog recovery
preserves output latches. The inactive game's sound board is held in reset.
Audio is signed 16-bit mono, duplicated to both MiSTer channels.
The mixer has one continuously clocked pipeline stage before the DC filter,
adding 20 ns at 50 MHz. Rip Off's arithmetic uses ordinary single-cycle timing.

The oscillator tables are generated by `tools/prepare_ripoff_sound.py` from
component values and MAME's fitted full-circuit VCO half-period curves.
Background uses two OR-combined oscillator phases clocking a four-bit counter.
Beep is about 1452 Hz; the motor oscillators are about 51 and 138 Hz.
Explosion duration uses 1.1*470k*.68uF = .35156 s.

This is a behavioral approximation. Sweeps use normalized 0-5 V control levels,
32-step frequency lookup and power-of-two RC smoothing. The noise filters,
OTA gains, mixer levels, loading, nonlinearities and analog coupling need
calibration against recordings or an original board. MAME's netlist also
contains explicitly documented switching/gain workarounds; no claim of exact
netlist waveform agreement is made. No audio samples or sound ROMs are used.

`bash sim/run_ripoff.sh` checks profile selection/rejection, legacy fallback,
service polarity, separate controller/keyboard mapping and the shared machine.
An optional locally prepared `build/roms/ripoff.bin` enables CPU differential
and full-frame gameplay regression with both players' controls exercised.
`bash sim/run_ripoff_sound.sh` checks serial commands, six voices, release,
mixer headroom, sample rate and short triggers. CI uses no game ROMs.

Hardware playability and listening require MiSTer testing. Build evidence and
hardware status belong in the release manifest; simulation is not a hardware test.
